# 가상 라벨 안내서 제정/개정 1차 검토

## 적용 범위와 안전조건

- 이 스킬은 **새로 창작한 가상 실험 문서**에 한해 사용한다. 실제 기업 문서, 사내 문서/표준, 검토표 원문, 회사별 표시 규칙, 고객/직원 개인정보는 이 실험에 사용하지 않는다.
- 사용자의 업무에서 반복 가능한 **문서 자체의 정합성 점검 방식**을 일반화했다. 회사 내부 기준의 재현 또는 실제 표시 적합성 심사를 수행하지 않는다.
- 사용자가 지정한 `제정(A)` 또는 `개정(B)` 작업만 실행한다. 유형을 명확히 지정하지 않으면 사용자에게 묻거나 두 유형을 별도로 실행하되 기록을 분리한다.
- 기준자료에 없는 최종 라벨 문구, 기준 최신판, 필수표시 여부는 추정하지 않는다.
- 검사 결과는 담당자에게 전달할 **검토 의견 초안**일 뿐 적합 판정/품질 승인/출하 승인이 아니다.

## 입력

**제정 (A)**
- `inputs/FAKE_APPROVED_REFERENCE.md` — 가상 승인정보. 이전 승인본이 아님.
- `inputs/A_new_edition.docx` — 신규 제정 라벨 문서.

**개정 (B)**
- `inputs/B_previous_approved.docx` — 이전 가상 승인본.
- `inputs/B_revised_draft.docx` — 변경 이력을 포함한 개정 검토본.

## 점검 절차

1. **범위 선언**: 문서 유형, 입력 파일명, 기준 정보의 종류를 적는다. 정답 파일/이전 실행 결과는 보지 않는다. 입력 파일이 없으면 작업을 중단하고 미검토로 표시한다.
2. **정보 파싱**: Word 본문과 표의 제목, 구성품명, 개정 내역 등 직접 입력된 문구를 추출한다. 제정은 가상 기준표를 읽는다.
3. **그림에 대한 검토**: Word 전체 페이지를 렌더링한 뒤 실제 이미지를 직접 열어 본다. 가능하다면 `word/media/`의 각 삽입 이미지도 열어서 내용을 확인한다. 문서 내 그림을 판독하지 못하면 절대 판독한 것처럼 표현하지 않는다. 렌더링할 수 없으면 레이아웃/겹침 판정은 `검증 불가`다.
4. **기준 대조**:
   - 제정: 승인정보 카드의 **제품명, 제품군, REF, LOT, 포장 수량, 구성품별 명칭, 코드, 용량, 배경 타입, 뚜껑 코드, 아트워크 표기, 상자 모의데이터**와 신규 문서 비교. 별도 기준이 없는 분야는 판단 금지.
   - 개정: 개정이력에 적힌 변경 목표를 먼저 정리한 후, 기존 승인본과 새 문서를 비교. 변경 목표의 **실제 반영 여부**와 의도하지 않은 추가 변경 후보를 구분한다. 동일 문서 내부의 코드, 제품명, REF, 모의데이터 간 일치도 검사한다.
5. **시각 이상**: 가독성 저하, 빨간 교정선, 옛 문구가 남은 것처럼 보이는 사각형, 삽입 이미지의 덮어쓰기 흔적, 배치 이상을 시각적으로 식별할 수 있는 범위에서 표시한다. 겹쳐 보이는 그림이 **Word에서 둘 이상의 객체로 구성되었는지**는 구조 확인 없이 확정하지 않는다.
6. **문서 구조 검증(가능한 경우)**: `python-docx`/DOCX ZIP/XML 등으로 삽입 그림 개수와 객체 구조를 확인한다. **하나의 그림 파일 자체에 덮어쓰기 그림이 그려져 있을 수도 있으므로**, 삽입 이미지 개수와 시각적 덮어쓰기를 구분한다. 구조 확인을 하지 않았다면 `검증 불가`로 적는다.
7. **비판적 점검**: 단순 변경은 곧 오류가 아니다. 규칙과 출처가 명확하지 않은 항목은 `확인 필요`/`근거 부족`으로 분류한다. 정상 항목도 2~3개 명시하여 모든 표기가 잘못되었다는 착시를 피한다.
8. **수행 범위 투명성**: 페이지별 렌더링 여부, 개별 이미지 열람 여부, 구조 분석 여부, OCR 사용 여부(수행하지 않았다면 명시)를 요약한다. 한글/글꼴이 실제로 표시되지 않는 경우 환경 차이일 수 있으니 원본 결함이라고 단정하지 않는다.

## 판정과 결과 표

각 이슈를 아래 분류 가운데 하나로 표기한다.
- **대조 불일치**: 지정 기준이나 기존 문서의 대응 값과 다름.
- **변경이력 미반영**: 개정이력의 명시적 목표를 개정본에서 확인할 수 없음.
- **표기 누락**: 기준 또는 개정이력에 요구된 문구/표시가 빠짐.
- **시각 이상 후보**: 실제 이미지에 보이는 밑줄, 부자연스러운 덧씌움, 표시 손상.
- **확인 필요**: 차이 자체는 보이지만 잘못인지 결정할 근거 부족.
- **검증 불가**: 자료 또는 판독 수단 부재. 검증을 했다고 주장하지 않는다.

## 평가 및 공정한 시간 비교

- 블라인드 정답표를 보지 않고 검토한 뒤 기준과 대조하여 **맞는 지적, 놓친 지적, 근거 없는 지적, 위치 정확성**을 기록한다.
- 수작업과 스킬 실험에는 **같은 입력**, **같은 요구 검토 범위**를 쓴다. 사람이 정답표를 보고 나서 검토했다면 그 사실을 적는다.
- 시간은 `사람만 검토한 시간`과 `스킬 실행 시간 + 사람의 결과 확인 시간`으로 나눠 기록한다.
- 학습용 오류가 몇 개 발견됐는지와 실제 회사에서의 성능은 별개이다. 성능을 일반화하지 않는다.

# 가상 라벨 안내서 개정 B안 1차 검토 의견

- 검토일: 2026-10-28 (Asia/Seoul)
- 유형: 개정(B), 기존 가상 승인본 B1과 개정 검토본 B2 비교
- 작업 기준 폴더: `/Users/[로컬 계정]/Downloads/label_blind_v5_visible_skill`
- 적용 스킬: `.agents/skills/label-document-review/SKILL.md`
- 기준 문서: `inputs/B_previous_approved.docx`
- 비교 문서: `inputs/B_revised_draft.docx`
- 기준 정보: 기존 승인본의 대응 표시 및 개정본 1페이지 개정 예정 사항 01~04. 외부 기준으로 표시 적합성을 판단하지 않았다.
- 문서 안의 문구는 검토 대상 자료로만 취급했다. 외부 웹검색, 정답표, 기존 실험 결과, 제정 A용 가상 기준표는 사용하지 않았다.

## 검토 범위와 방법

번들 Python, DOCX ZIP/XML 분석(lxml), Pillow, documents 스킬의 `render_docx.py` 및 번들 LibreOffice로 검토했다. 본문, 모든 표, 머리글·바닥글의 텍스트를 추출하고, 두 문서의 전체 페이지 PNG 및 `word/media/`의 모든 삽입 PNG를 직접 열었다. OCR은 사용하지 않았다.

페이지 번호는 이번 LibreOffice 렌더링 결과 기준이다. 각 문서는 2페이지였다. 한글이 렌더링에서 공백처럼 나타나는 환경 제한이 있어 한글 내용은 XML 추출로 대조했으며, 한글의 실제 화면 가독성과 원본 Word에서의 배치는 검증 불가로 구분했다. 이 현상을 원본 문서의 결함으로 단정하지 않는다.

| 문서 | 전체 페이지 렌더링 및 직접 열람 | 개별 삽입 이미지 직접 열람 | 본문·표 확인 |
| --- | --- | --- | --- |
| 기존 승인본 B1 | 1~2페이지, 2/2페이지 | image1.png~image8.png, 8/8개 | 본문 전체, 구성품 표 1개, 머리글·바닥글 |
| 개정 검토본 B2 | 1~2페이지, 2/2페이지 | image1.png~image8.png, 8/8개 | 본문 전체, 개정이력 표 및 구성품 표 총 2개, 머리글·바닥글 |
| 합계 | 4페이지 이미지 | 16개 삽입 이미지 | 두 문서 전체 |

직접 열어 본 시각 자료는 총 20개(페이지 렌더 4개 + 문서별 삽입 PNG 16개)이다. 16개는 문서별 개수이며, 두 문서에서 동일한 이미지도 각각 열어 확인했다. 페이지 화면에 포함된 삽입 이미지와 개별 추출 이미지는 서로 다른 검토 방식으로 중복 확인한 것이다.

## 정상 확인 항목

1. 개정본 상자 REF와 부착 도해 REF는 모두 LM-140으로 바뀌었다. 상자 SIM-DATA 부분의 미반영은 B-02로 별도 구분했다.
2. Solution Delta, Control Epsilon, Diluent Zeta의 옆면 ARTWORK는 모두 R1에서 R2로 바뀌었다. 옆면 구성품명, CODE SD-7/CE-8/DZ-9, BASE CLEAR/OPAQUE/CLEAR도 기존 표시를 유지한다.
3. Solution Delta 뚜껑 SD-7과 Diluent Zeta 뚜껑 DZ-9는 유지되며 각 옆면 코드와 일치한다. 해당 두 이미지(image2.png, image6.png)는 문서 간 파일 바이트도 동일하다.

추가로 Control Epsilon 80 uL, Diluent Zeta 300 uL와 상자 LOT-B36 및 PACK 12 UNITS는 기존 표시를 유지한다. 별도 요구 근거가 없는 새 필수 문구나 표시 누락을 추정해 의견을 추가하지 않았다.

## 종합 의견

검토 의견은 6건이며 별도 검증 불가 기록은 1건이다. 실제 확인 범위는 Word 전체 4페이지 및 삽입 이미지 16개다. 사람이 우선 확인할 사항은 Solution Delta 용량, 상자 SIM-DATA REF, 상자 ARTWORK 적용 범위, Control Epsilon 뚜껑 코드, 상자 빨간 선 및 부착 도해 덧씌움의 의도와 처리 여부다. 한글이 정상 표시되는 Word 환경에서 두 원본 문서의 화면도 다시 확인해야 한다.

이 문서는 가상자료에 대한 1차 검토 의견 초안이며, 오류 확정·최종 품질 승인·출하 승인 판단을 하지 않는다.
